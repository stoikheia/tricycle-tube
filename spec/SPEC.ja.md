# 描画仕様 v0.5（草稿）— ファミコン映像のコンポジット信号とブラウン管表示の再現

版: v0.6 草稿（2026-10-07）。英語版 [SPEC.md](SPEC.md) が正で、本書はその日本語版。試作（`crt_pipeline.py`）の挙動を書き起こし、フレーム位相と YIQ→RGB の係数を訂正したもの（経緯は §12）。参照実装は [reference/crt_reference.py](../reference/crt_reference.py)。
このプロジェクトの本体。この文書と適合ベクタ（[conformance/vectors.json](../conformance/vectors.json)）だけを AI エージェントに渡せば、新規のエミュレータにも既存エミュレータの改造にも同じ描画を実装できることを目標にする。

読み方: 「**規範**」と書いた節は実装が従う内容。「背景」は理由の説明で、環境に合わせて実装を変えるときの判断材料。§10 は未決事項で、決まりしだい規範に反映する。

## 1. 用語

- **パレット番号**: PPU（ファミコンの映像回路 2C02）が画素ごとに出す 6 ビット値 `$00〜$3F`。下位 4 ビットが色相番号、上位 2 ビットが輝度段
- **コンポジット信号**: 輝度と色を 1 本に重ねた映像信号。ファミコンは RGB を経由せず、この信号を直接作る
- **副搬送波**: 色を運ぶ約 3.58MHz の波。この仕様では 1 周期 = 12 サンプル
- **サンプル**: 信号を刻む最小単位。1 画素 = 8 サンプル
- **位相**: 副搬送波 1 周期のどこにいるか（0〜11）
- **Y / I / Q**: 輝度と 2 つの色差
- **走査線**: ブラウン管が横に描く 1 本の線。ファミコンの 1 画素行に対応
- **蛍光体ストライプ**: 画面に縦に並ぶ赤・緑・青の発光体の列
- **残光**: 蛍光体が光り終わるまでの尾。ここでは前フレームとの重ね合わせで表す
- **ホスト**: この描画を組み込む側（エミュレータ本体、シェーダを読み込むフロントエンドなど）

## 2. 全体の流れ（規範）

入力は「パレット番号の画像」と「フレーム位相」。出力は表示用の RGB 画像。

```
パレット番号 W×H ＋ フレーム位相 P
  → [信号段]      コンポジットに符号化して復号   → RGB 8W×H
  → [ブラウン管段] 縦に k 倍、走査線・ストライプ・ブルーム → RGB 8W×kH
  → [残光段]      直近 3 フレームを合成          → RGB 8W×kH
  → [縮小段]      面積平均で表示サイズへ         → RGB 任意サイズ
```

- 標準は W=256、H=240、k=12（中間画像 2048×2880）。**中間画像の大きさは表示サイズによらず固定**
- 各段の値は 0〜255 のガンマ符号化された値のまま計算する（線形光への変換はしない）
- 段と段の間で受け渡す画像は 8 ビット整数の RGB。段の中の計算は倍精度の浮動小数で行い、整数に落とす位置は各節の式のとおり
- 範囲外の添字は端の値を繰り返す。この仕様のすべての平均・ぼかし・補間に適用する。平均を重ねるときは、1 回ごとに、その回の入力の配列に対して端を繰り返す（信号を外へ延ばしてからまとめて処理するのではない）
- 幾何学的な歪み、ゴースト、電波段の劣化（スノー・ハム・離調）は含まない

背景: 中間画像を固定するのは、走査線とストライプの構造を窓の大きさと無関係に同じにするため。小さい窓では同じ構造を縮小して見せる。

## 3. 入力（規範）

### 3.1 必須の入力

1. 画素ごとのパレット番号（6 ビット）。色に変換する前の値
2. フレーム位相 P（0〜11。そのフレームの先頭での副搬送波の位相）。求め方は §3.3

起点: P は表示画素 (0, 0) の最初のサンプルの位相。240 行の画面全体の行 y は `P + 4y` から始まる。ホストがこのパイプラインの前で行を切り落とす場合は、元の行番号を保つ（例: 8 行目から始まる画像は最初の行を y = 8 とする）。パレット番号は PPU のグレースケール処理の後の値を渡す（PPUMASK のグレースケールが有効なら `index & $30`）。

### 3.2 ホスト別の取り方

| ホスト | 取り方 |
|---|---|
| 新規のエミュレータ | PPU の出力を RGB に変換する前のバッファを渡す |
| 既存エミュレータの改造 | パレット変換の直前に割り込む（例: Mesen 系は 9 ビットの PPU 出力バッファを映像フィルタに渡している） |
| RetroArch のシェーダ | コアのパレット設定を raw にすると、R = 色相番号/15、G = 輝度段/3、B = 強調ビット/7 で届く。復元は `floor(R*15+0.5)`、`floor(G*3+0.5)`、`floor(B*7+0.5)` |
| RGB しか取れないホスト | ホストが使っている 64 色の表から最近傍のパレット番号へ逆引きする。同じ色に写る番号が複数あるときは `$0F` を黒の代表にする。忠実度は落ちる |

強調ビット（PPU の色強調 3 ビット）はこの版では使わない（§10）。

### 3.3 フレーム位相

フレームは 0 から数える。最初のフレーム（フレーム 0）を P = 0 とし、フレームが終わるたびに、そのフレームの長さ（ドット数）から次を求める。

```
P_次 = (P + 8 * ドット数) mod 12
```

- 1 フレームは 341 × 262 = 89342 ドット。このとき P は +4 進む
- 描画が有効な間は、番号が奇数のフレームが 1 ドット短い（89341 ドット）。このとき P は +8 進む
- したがって描画中は 0, 4, 0, 4, … の **2 フレーム周期**、描画を止めている間は 0, 4, 8, 0, … の 3 フレーム周期になる

ホスト別:

| ホスト | 求め方 |
|---|---|
| 新規のエミュレータ、既存エミュレータの改造 | PPU が実際に出したドット数を毎フレーム積算する。描画の有効・無効による違いが自動で出る |
| フレーム番号 f しか分からないホスト（シェーダなど） | 固定 3 周期（既定）: P = 4 × (f mod 3)。固定 2 周期、またはドット数の無い実機追従: f が偶数なら P = 0、奇数なら P = 4（常に描画中とみなす） |

**表示位相モード**: 位相の進め方は表示側の設定として選べる。

| モード | ドット数として入れる値 | 位相の列 |
|---|---|---|
| 固定 3 周期（**既定**） | 常に 89342 | 0, 4, 8, 0, … |
| 実機追従 | PPU が実際に出したドット数 | 描画中 0, 4, 0, 4, …／描画停止中 0, 4, 8, … |
| 固定 2 周期 | 89342 と 89341 を交互 | 0, 4, 0, 4, … |

既定を固定 3 周期とするのは表示上の選択（2026-10-04 決定: にじみの再現性を保ちつつ、偽色の色相が回り続けるちらつきと流れる模様を出す。実機の通常動作は 2 周期）。残光段（§6）の同位相の探索はどのモードでも同じ規則で働く。

## 4. 信号段（規範）

1 行ずつ独立に処理する。行 y（0 始まり）の行頭位相は、フレーム位相 P（§3.3）から

```
phase0 = (P + 4*y) mod 12
```

背景: 1 行は 341 画素 × 8 サンプル = 2728 サンプルで、12 で割ると 4 余る。行ごとに位相が 1/3 周期ずれ、3 行で一巡する。

### 4.1 符号化（パレット番号 → 信号）

定数（電圧。実機の実測値）:

```
LO = [0.228, 0.312, 0.552, 0.880]
HI = [0.616, 0.840, 1.100, 1.100]
黒 = 0.312、白 = 1.100
```

画素 x のパレット番号 pix について

```
color = pix & 0x0F
lvl   = (pix >> 4) & 3
color > 13 のとき lvl = 1
lo = LO[lvl]、hi = HI[lvl]
color == 0  のとき lo = hi
color == 13 のとき hi = lo
```

画素 x の 8 サンプル（p = 0〜7、行内のサンプル番号 s = 8x + p）それぞれについて

```
ph = (phase0 + s) mod 12
高い側か = (color == 0) または (color < 13 かつ ((color + ph + 8) mod 12) < 6)
v = 高い側なら hi、そうでなければ lo
sig[s] = (v - 0.312) / (1.100 - 0.312)
```

背景: 色相番号 1〜12 は、12 サンプル周期・デューティ 50% の矩形波で、番号ごとに位相が 1 サンプルずつずれる。番号 0 は高い側だけ（灰〜白）、13 は低い側だけ、14・15 は黒。

### 4.2 復号（信号 → RGB）

行のサンプル数を n = 8W とする。

箱型平均を `box(a, r)[i] = mean(a[i-r .. i+r])`（2r+1 個の合計 ÷ 個数）と書く。

```
N[i]  = (sig[i-3] + sig[i+3]) / 2       … 半周期離れた 2 点の平均（ノッチ）
Y     = box(N, 1)
C[i]  = sig[i] - Y[i]
ang_i = π * ((phase0 + i) mod 12) / 6 + rot
Iraw[i] = C[i] * cos(ang_i)
Qraw[i] = C[i] * sin(ang_i)
I = box(box(Iraw, 8), 8)
Q = box(box(Qraw, 14), 14)
```

出力の列 c（0 〜 cols-1、標準は cols = n）は、サンプル `s = min(n-1, floor((c + 0.5) * n / cols))` の値を使う。

```
y = Y[s]、i = sat * I[s]、q = sat * Q[s]        sat = 1.6
R = y + 0.955986*i + 0.620825*q
G = y - 0.272013*i - 0.647204*q
B = y - 1.106740*i + 1.704230*q
各成分 = clamp(floor(成分*255 + 0.5), 0, 255)
```

`rot`（色相の回転）= **350°**（ラジアンにして使う）。決め方は §4.3。

背景:
- 半周期（6 サンプル）離れた 2 点は副搬送波の符号が逆なので、平均すると色の成分が打ち消されて輝度だけが残る。足跡が 7 サンプルと短いので、1 ドット（8 サンプル）の黒がほぼ黒のまま残る。そのあとの 3 個平均は輪郭をわずかに丸める。代償として色の境目に細い縦縞が出る
- 試作は 12 個の移動平均（1 周期ぶん）＋5 個平均だった（`mean(sig[i-6 .. i+5])` → `box(·, 2)`）。孤立した黒が灰色に浮く（孤立黒 60 画素の平均輝度 46.8 → ノッチ 35.3）ため、2026-10-04 にノッチを既定にした。参照実装では `LUMA_MEAN12` として残してある
- 色差は副搬送波と掛け合わせて取り出し、二重の箱型平均で低域に絞る。1 ドット 8 サンプル（約 42.95 MHz）の標本化では、−3 dB 点は I が約 0.81 MHz、Q が約 0.47 MHz（最初の零点は 2.53 MHz と 1.48 MHz）。幅は見た目で選んだもので、NTSC の公称の I/Q 帯域（1.3 / 0.6 MHz）より狭い。色が横ににじみ、細かい模様に虹色が乗る（クロスカラー）のはここから自然に出る
- rot は、`$16` が最も赤く、`$1A` が最も緑に、`$12` が最も青くなる角度（§4.3）
- RGB への係数は標準の定義から導いた値（小数 6 桁）。Y = 0.299R + 0.587G + 0.114B、U = 0.492111(B − Y)、V = 0.877283(R − Y)、I = −U sin33° + V cos33°、Q = U cos33° + V sin33° の逆変換
- 彩度 1.6 と、ノッチの輝度フィルタ、箱型 2 回の帯域制限は、このプロジェクトの試作とサンプル検証で見た目から決めた簡易な構成

### 4.3 色相回転の決め方

0°, 5°, …, 355° の 72 通りについて次の得点を計算し、最大の角度を rot とする。同点なら小さい角度。

- 対象は 3 色: `$16`（狙う成分 R）、`$1A`（G）、`$12`（B）
- それぞれ、その色だけの 64 画素の行を phase0 = 0 で符号化・復号し（phase0 は直接与える）、cols = 64 としたときの列 32 の RGB を取る。**丸めて 0〜255 に収めた後の整数値**を使う
- 得点 = 3 色について `狙った成分 − 他 2 成分の平均` を足したもの

結果は 350°。丸める前の浮動小数で得点を取ると別の角度になりうるので、必ず丸めた後の値で取る。係数を変えたらこの手順でやり直す。

## 5. ブラウン管段（規範）

入力は信号段の RGB（幅 cols、高さ H）。出力は幅 cols、高さ kH。

既定値: k = 12、強さ s = 0.6、gap = 0.33、ストライプ周期 = 9、スポット半径 = 1、ブルーム = 0.15。

手順:

1. **縦に k 倍**（最近傍）。出力行 Y の元の行は `floor(Y / k)`。横はそのまま
2. **ビームスポット**: 半径 1 の箱型平均（3 個）を横にかけて切り捨て、整数にする。その整数の画像に同じ平均を縦にかけ、もう一度切り捨てる（切り捨ては方向ごと。縦は拡大後の画像の行に対して行う）
3. **走査線**: 出力行 Y の係数。j = Y mod k として
   `prof[j] = 1 - s * (1 - exp(-((j + 0.5 - k/2) / (k * gap))^2))`
4. **蛍光体ストライプ**: 出力列 X の係数。m = X mod 周期、t = floor(3m / 周期) として、(R, G, B) にかける係数は t = 0 なら (1, d, d)、t = 1 なら (d, 1, d)、t = 2 なら (d, d, 1)。d = 1 − 0.3s
5. **合成**: 成分ごとに `out = min(255, floor(スポット後の値 * prof * その成分のストライプ係数 * gain + 0.5))`、gain = 1 + 0.3s。out は整数
6. **ブルーム**: 信号段の RGB（拡大前）に、半径 3（7 個）の箱型平均を横にかけて切り捨て、その整数の画像に半径 2（5 個）の箱型平均を縦にかけて切り捨てる。これを縦 k 倍へ双線形で拡大する（横はそのまま）。拡大は画素中心基準で、出力行 Y の元座標を `v = (Y + 0.5)/k − 0.5` とし、上の行 `y0 = clamp(floor(v), 0, H−1)`、下の行 `y1 = min(H−1, y0 + 1)`、割合 `u = clamp(v − y0, 0, 1)` から `a*(1−u) + b*u` を求め、`floor(x + 0.5)` で整数にする。
   最後に成分ごとに `out = min(255, floor(手順 5 の out + ブルーム画像 * ブルーム * s))`

k を変えるとき、ストライプ周期の既定は `max(3, floor(k / 1.3 + 0.5))`（k = 12 なら 9）。

背景: NTSC のファミコンの PPU（2C02）は 1 フレーム 262 行を出し（一部の奇数フレームではプリレンダー行が 1 ドット短い。§3.3）、垂直同期に半行のずれを入れないので、ブラウン管は毎フレーム同じ走査線の上に重ねて描く（240p。インターレースは起きない）。ビームの軌跡と軌跡の間が暗いまま残るのが走査線の見え方で、ここではそれを 1 走査線 k 行のガウス形で表す。走査線は行の中央が明るく上下が暗いガウス形で、gap がビームの太さ。ストライプと走査線で暗くなるぶんを gain で補う。ブルームは明るい部分のまわりの淡い光。

## 6. 残光段（規範）

入力はブラウン管段の出力の時系列 F[f] と、各フレームのフレーム位相 P[f]。重みは現在 : 1 つ前 : 2 つ前 = 6 : 3 : 1（0.6 / 0.3 / 0.1）。

**同位相のフレーム** S を決める: f−2、f−3 のうち、存在して P が P[f] と等しいフレーム（両方が同時に等しくなることはない）。無ければ「なし」。

画素ごと、成分ごとに

```
S があるとき  d = |F[f].r - S.r| + |F[f].g - S.g| + |F[f].b - S.b|
S があり d > 24 なら   out = F[f]                       （動いている画素。残光なし）
それ以外               out = (6*F[f] + 3*F[f-1] + 1*F[f-2] + 5) div 10     （div は整数の切り捨て除算）
```

- 合成は整数で定義する（0.6 などを浮動小数で掛けて足すと、端数がちょうど 0.5 の画素で結果が割れる）。重みを w0 : w1 : w2 に変えるときは、合計を T として `(2*(w0*a + w1*b + w2*c) + T) div (2*T)`
- 合成するのは合成前の画像どうし（出力を次のフレームへ戻す形ではない）
- 残光はエミュレートしたフレームごとに進める。画面の更新が 30Hz でも、提示する絵は直近 3 フレームを合成したもの
- 過去のフレームが存在しないとき（フレーム 0 と 1）は、存在しないものだけを現在のフレームで代用する。フレーム 1 なら F[f−1] = F[0]、F[f−2] は F[1] で代用。S は実在するフレームからだけ選ぶ（フレーム 0・1 では「なし」、フレーム 2 では F[0] が候補）
- 位相の列が 0, 4, 0, 4（2 フレーム周期）なら S = F[f−2]、0, 4, 8（3 フレーム周期。既定の固定モードを含む）なら S = F[f−3] になる。保持する過去フレームは 3 枚
- 許容する変種（軽量）: この段を信号段の画像（8W×H）に対して行い、その後にブラウン管段を通す。合成は線形なのでほぼ同じ絵になるが、255 での飽和と動き判定のしきい値が別の値に効くため、`persistence` と `area_average` のベクタには一致しない前提とし、変種を使うことを明示する。履歴を信号段の大きさで持ち、過去フレームごとにブラウン管段を再計算する形（§8）はこの変種ではなく、規範どおりの順序である

背景: 行頭位相がフレームごとに変わるので、虹色の出方は毎フレーム変わる。実機では残光と目がこれをならす。液晶には残光が無いので、合成で補う。動きの判定に同位相のフレームを使うのは、位相が同じなら静止画素の値が一致するため。輝度だけで比べないのは、ファミコンには明るさが同じで色相だけ違う色が多いため。

参考: 重み 6 : 3 : 1 は 3 フレーム周期の試作で選んだ値（2026-10-04 に既定として決定）。2 フレーム周期では位相が 2 種類しかなく、どう重ねても虹色は打ち消しきれない。白黒 1 画素の市松での計測（信号段の出力、彩度 = 最大成分 − 最小成分の平均）は、1 フレーム単独 94.3、3 フレーム周期でこの重み 41.1、2 フレーム周期でこの重み 57.3、2 フレーム周期で 5 : 5 なら 47.2。

## 7. 縮小段（規範）

中間画像（8W × kH）を表示サイズへ**面積平均**で縮小する。出力画素が覆う範囲に重なる元画素を、重なりの面積で重み付けして平均する。

- 横方向: 出力列 o が覆う元の範囲は `[o * 元幅 / 出力幅, (o+1) * 元幅 / 出力幅)`。この範囲と各元画素 `[i, i+1)` との重なりの長さが横の重み。縦も同じ
- 元画素の重み = 横の重み × 縦の重み。成分ごとに `重みつきの和 ÷ 重みの合計` を求め、`floor(x + 0.5)` で整数にする
- 縮小率が 1/2 を下回る場合に 2 点の双線形補間を使ってはならない（走査線とストライプが縞模様に化ける）
- 出力の大きさ、表示の縦横比（4:3 相当か正方画素か）、上下の切り落とし（240 行か 224 行か）はホストが決める。この段は、ホストが決めた大きさへの縮小のしかたを定める

## 8. 実装の形ごとの指針（背景）

| 形 | 指針 |
|---|---|
| CPU での参照実装 | §4〜§7 をそのまま書く。適合ベクタと 1 画素単位で一致させる |
| GPU の多段描画 | 信号段は横 8 倍の中間画像に、Y と色差を浮動小数で書く段と、帯域制限して RGB にする段の 2 段に分ける。縮小は出力画素の覆う範囲を明示的に積分する。**残光の履歴は信号段の小さい画像（8W×H）で持ち、ブラウン管段と残光段を 1 パスにまとめて現在と過去のフレームをその場で再計算する**と、§6 の意味（ブラウン管段の後で合成）を変えずに大きな画像を 3 枚保持せずに済む。同じ位相で内容が同一のフレームは再計算を省ける。実績: Apple GPU（Metal）で窓 2340×1792 に約 4.9 ms/フレーム、3762×2880 に約 6.2 ms/フレーム（別プロジェクトの WGSL 実装、2026-10-04） |
| RetroArch の slang シェーダ | 上と同じ。過去フレームはフィードバックとコピー用パスで保持する。構成案は非公開の調査メモ |
| 既存エミュレータの改造 | パレット変換の直前でパレット番号を取り、そのエミュレータの映像フィルタの位置に差し込む。改造したエミュレータの配布はそのライセンス（多くは GPL）に従う |

浮動小数で実装すると、試作の整数丸め（切り捨て・四捨五入）とは最大 1/255 ほどずれる。§9 の許容差はこれを見込んでいる。

## 9. 適合の確認（規範）

[conformance/vectors.json](../conformance/vectors.json) に参照実装の出力を収めてある。

試験に使う入力（どの行も同じ番号列を 3 行並べた 16×3 の画像。cols = 128、k = 12）:

```
模様 A: 0F 30 0F 30 16 16 2A 2A 12 21 30 0F 27 27 1A 0F
模様 B: 30 0F 16 21 16 16 2A 2A 12 21 30 0F 27 27 1A 0F     （先頭 4 画素だけ A と違う）
```

| 項目 | 内容 | 許容差 |
|---|---|---|
| `frame_phases` | §3.3 の位相の列（描画中と描画停止中、各 8 フレーム） | 一致 |
| `hue_rotation_deg` | §4.3 の探索結果 | 一致（350） |
| `palette64_rgb` | 64 色それぞれの復号結果（§4.3 と同じ条件: 単色 64 画素、phase0 = 0、cols = 64、列 32） | 各成分 ±1 |
| `signal_pattern` | 模様 A をフレーム位相 0, 4, 8 で信号段に通した全画素。キーは `p<位相>_y<行>` | 各成分 ±1 |
| `crt_stage` | 模様 A・位相 0 の信号段の出力をブラウン管段に通した結果（128×36）。走査線係数 12 個（小数 6 桁に丸めて収録）、ハッシュ、行 6・11・12 の先頭 24 画素 | 係数は ±0.000001。画素は整数実装なら一致、浮動小数なら ±2 |
| `persistence` の `case_motion` | 描画中（位相 0, 4, 0, 4, 0, 4）。フレーム 0〜3 は模様 A、4〜5 は模様 B。各フレームの入力は、その模様をその位相で信号段とブラウン管段に通したもの。フレーム 0, 1, 3, 4, 5 の残光段の出力 | 整数実装なら一致、浮動小数なら ±2 |
| `persistence` の `case_rendering_off` | 描画停止中（位相 0, 4, 8, 0, 4, 8）。模様 A のまま。フレーム 5 の残光段の出力 | 同上 |
| `persistence` の `case_motion_fixed3` | 表示の既定（固定 3 周期。位相 0, 4, 8, 0, 4, 8）で動きあり。フレーム 0〜3 は模様 A、4〜5 は模様 B。フレーム 3, 4, 5 の残光段の出力（フレーム 5 は全画素を `frame5_output_rgb_hex` に収録） | 同上 |
| `moving_pixels_at_frame5` | `case_motion` のフレーム 5 で、S（フレーム 3）があり d > 24 と判定された画素の数。`total_pixels` は全画素数 | 整数実装なら一致 |
| `area_average` | `case_motion` のフレーム 3 の**残光段の出力**（128×36）を 50×13 へ縮小した全画素（`output_rgb_hex`） | 各成分 ±1 |

- ハッシュは SHA-256。対象は行優先・1 画素 3 バイト（R, G, B）・ヘッダなしの生のバイト列（128×36 なら 13824 バイト）。**検証は再現とは別の段階として扱う**: 実装は本仕様だけから書くが、浮動小数の実装をハッシュしか無い項目で確かめるには参照の画素が要り、それは参照実装（`reference/crt_reference.py`、`conformance/gen_vectors.py`）を実行して得る。実行は検証の一部であり、実装中に参照実装を読むことは再現に含まれない。参照実装から期待データを生成する形にしておくと、パイプラインに手を加えた利用者がその変更に合わせたベクタを作れる
- **許容差は段ごと**（その段の入力に参照実装の出力を与えたときの差）。全段を通した比較では各段の差が積み上がるので、通しの許容は ±4 とする（実績: WGSL 実装で通し 2）
- **動き判定の境目**: 実装のブラウン管段の出力が参照と各成分最大 ε ずれるとき、動きの差 d は参照から最大 6ε ずれるので、判定（d > 24）は参照の d が (24 − 6ε, 24 + 6ε] にある画素で逆に転びうる。転んだ画素の差は最大 0.4 × 255 ≈ 102（現在のフレームのみと 6 : 3 : 1 の合成の差）。これらの画素は残光の許容差の対象から外し、除外した数を報告する（ε = 2 なら参照の d が 13〜36）。ε を小さく保つため、段ごとに（前段に参照の出力を与えて）比べる。公開ベクタにはこの種の画素は含まれていない
- 行 6 は元の行の中央、行 11・12 は元の行の境目。ビームスポットの縦の平均は境目の行にしか効かないので、ハッシュが合わないときは境目の行で切り分ける
- ベクタのキーと仕様の用語: `strength` = 強さ s、`mask_period` = ストライプ周期、`spot` = スポット半径、`stripe_dim` = d、`gain` = gain、`output_size` = [幅, 高さ]
- `vectors.json` の `spec_version` は、出力が変わった最後の仕様の版（現在 v0.4）。文章の明確化だけの版ではベクタを変えない
- `palette64_rgb` のキーは 16 進 2 桁の大文字。`lines` などの `*_hex` の値は 1 画素 3 バイトの 16 進を連結したもの
- 試作そのものの出力（訂正前）は `conformance/vectors-v0-prototype.json` に残してある。参照実装は、試作の係数・12 個平均の輝度フィルタ・位相 0, 4, 8 を与えるとこれに一致する（`gen_vectors.py` が毎回確認）。v0.3（12 個平均・標準係数）のベクタは `conformance/vectors-v0.3-mean12.json`

確認用の代表値: `$0F` = (0,0,0)、`$00` = (98,98,98)、`$10` = (171,171,171)、`$20` = `$30` = (255,255,255)、`$16` = (174,57,2)、`$1A` = (0,147,0)、`$12` = (82,52,255)、`$21` = (111,164,255)、`$27` = (222,169,9)、`$2A` = (78,230,68)。

## 10. 未決事項

| 記号 | 事項 | 現状（v0.6） |
|---|---|---|
| D-同位相なし | 位相の並びが切り替わる瞬間など、同位相のフレームが無いときの扱い | 動きの判定をせず残光をかける（暫定） |
| D-強調 | 強調ビットへの対応。減衰後の電圧表は出典に記載がある。DQ3 では観測範囲で常に 0（WGSL 実装の所見） | 未対応 |
| D-雑音 | 試作にある位相雑音（既定で切）を仕様に含めるか。WGSL 実装は独自の暫定方式（行ごと最大 1°）を既定オフ・実験的として持つ | 含めない |
| D-ベクタ | ベクタが覆っていない規範: 同位相のフレームが無い場合、k ≠ 12 とストライプ周期の自動決定（`round` の端数の扱いを含む）、周期が 3 で割り切れないストライプ、cols ≠ 8W の一般の場合、標準サイズ（256×240） | 未作成 |

決着したもの: フレーム位相は実際のフレーム長から積算（§3.3）。YIQ→RGB の係数は標準の定義から導いた値（§4.2）。表示位相モードの既定は固定 3 周期、残光の重みは 6 : 3 : 1、輝度フィルタはノッチ（2026-10-04 決定。切り替えは将来の設定）。中間画像の横幅は 8W を規範（8W を超える窓では縮小段が横方向に拡大になり、マスクにかすかなうなりが出うる）、残光はブラウン管段の後に行い、軽量な順序は明示した変種として許容（§6）（2026-10-06 決定）。
